v1.37.0

One request, followed all the way through

A request lerd serves while debug capture is on now carries one id from nginx to PHP to the browser, so it opens on a timeline of everything it ran, its page reports its own errors back, and an assistant reads it over MCP led by what went wrong. The site header learned fetch, pull, push and branch switching, with the installs and migrations a move needs offered and the database snapshotted first. Services sleep when nothing uses them, secrets can come from a manager without touching .env, and the dashboard dropped from over a gigabyte to under 100 MB on a busy machine.

FEATUI

Every captured event already wore a request id, but nothing outside PHP knew it. Now PHP answers with an X-Lerd-Rid header, nginx writes it into its access log and the page carries it, so a recent request opens on a timeline of everything it ran, laid out on the time nginx measured. #2150 #2161

FEAT

Browser logs #2123 #2139

lerd browser-logs on injects a small script that reports uncaught errors, unhandled rejections, console messages and failed fetches, each tied to the request that served the page. Store presets add a frontend library's own events.

FEAT

A request tool that says what went wrong #2169

Over MCP an assistant lists recent requests and reads one, and its lenses action leads with N+1 and slow queries, then exceptions, error logs, failed HTTP calls, jobs and browser errors, each counted once.

FEATUI

Copy for agent #2170

The inspect dialog, a failing doctor check and an App logs entry copy a short prompt naming the MCP call that reads the full data, rather than a dump that goes stale or gets cut.

FEAT

The slowest request stays openable #2172 #2230

The slowest routes list spans seven days, but a bar could only open its request while its events were still in the buffer. The events of each route's slowest request are now kept aside, survive a restart and are let go once it stops being the slowest. A bar with nothing kept says why, and offers to turn capture on when it is off.

FEAT

Idle-suspend could already put a site's workers to sleep. With lerd idle services on it does the same for databases, caches and mail catchers once every site and worktree using them has gone quiet. #2008

A browser, an API client or a webhook never sees a waking page. Console commands, MCP calls and the databases tab wake what they need, and a pinned service stays up.
FEAT

Secrets from an env_provider, kept in tmpfs #2069

A project whose secrets live in a manager declares a command in .lerd.yaml, such as infisical export --format=dotenv. lerd runs it behind the host command consent gate and keeps the output in a 0600 file under $XDG_RUNTIME_DIR that PHP loads for web requests, workers and the CLI, so the values never touch .env or container storage. The docs carry commands for Infisical, Doppler, 1Password, Bitwarden, sops, Vault and AWS.

A soft memory limit #2188

lerd-ui, the watcher, the tray and the MCP server aim at 64 MB unless GOMEMLIMIT says otherwise, so one large response no longer keeps a process several times its size for minutes.

05

Terminal

FEAT

The TUI is rebuilt around one sidebar and one main area, drawn in the terminal's own palette, and ctrl+p reaches every page, site, worktree, service, action and setting, matching words in any order. Destructive actions stay in the CLI. #2040

FEAT

DNS built into lerd #2146

lerd-dns was a dnsmasq container on Linux and a Homebrew dnsmasq on macOS. lerd dns-serve answers the TLD now, which drops the only image lerd built itself. An upgrade swaps it in with no sudo prompt.

FEATUI

FEAT

For apps that route their own .php URLs, like GLPI 11. Every .php request goes through index.php, and it travels in a committed .lerd.yaml.

FEATUI

06

Fixes

FIX

The fixed list covers bugs that shipped in 1.36.0 or earlier. Regressions introduced and fixed inside this cycle never reached anyone, so they are left out. Several of them passed silently: tests green, a status that read fine, a check that said unknown.

FIX

Pest's Chromium rejected lerd's certificates #2223

Chromium reads its own NSS store, so on a secured site with Vite running no script loaded, while text-only assertions and assertNoJavaScriptErrors stayed green.

FIX

The node audit on bun, pnpm and yarn #2221

The doctor always ran npm audit, which needs a package-lock.json. Each project is audited by its own package manager now.

FIX

A FrankenPHP site answered 502 #2191 #2111

Starting a worker re-rendered its vhost from the PHP-FPM template, and lerd start did not bring it back after a reinstall.

FIX

lerd's MySQL under a host AppArmor profile #2120

On Ubuntu or Debian with mysql-server installed, its profile attached to the mysqld in lerd's container too, which then could not read its config.

FIX

lerd rebuild took a custom container down #2195

It removed the running image before building the new one, while reporting success.

FIX

A worktree reinstalled every minute #2178

On npm 6 or Yarn 1 the marker the staleness check trusts is never written, so the watcher ran a clean install on every pass.
